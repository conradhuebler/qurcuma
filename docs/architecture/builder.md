# Molecule builder (Build mode)

Detail moved from `src/CLAUDE.md` (Oct 2026), text unchanged. Statements about code were not re-checked during the move.

- ✅ **Build mode** (`InteractionMode::Build`, viewer-bar "Build" split-button, Structure ▸ Build (key B), Esc steps back to View): click empty space = place atom of the current element at the selection's depth (`SceneController::screenToModelPoint`, inverse of the pick ray); click an atom = change it to the current element; **middle-click** an atom = attach a bonded atom along `freeValenceDirection` (−Σ unit bond vectors) at covalent distance; **right-click** an atom = delete it (elsewhere right-click keeps the context menu); drag = the atom follows the cursor LIVE (move intent); the atom always follows the cursor; bond intent is PROXIMITY-based (within 1.35 × Σrcov of an unbonded atom: highlight + REAL preview bond whose ORDER follows the current distance live — `build::bondOrderFromDistance`, C-C series ratios; release commits atom position and that order). Cursor directly on a bonded neighbour on release = cycle order (atom returns to start, it was a gesture) (removed on leave, committed via `buildBond` on release; `pickAtom` excludes the dragged atom so it cannot occlude the target); release on empty keeps the move (no bond re-detection — the builder keeps the drawn topology). **Ctrl+drag or held Space = pure navigation** (rotate) even from an atom; **Shift+drag on an atom = depth move** (Edit-mode convention; plane drags keep the atom's current depth); **keys 1/2/3 while a bond preview is on screen force the order** (`setForcedBondOrder`, ShortcutOverride-gated — without a preview they keep the render styles; the forced order dies with its preview). Carry previews always show order 1 (docking commits a single bond). Robustness: MouseMove re-syncs `m_leftMousePressed` from `me->buttons()` (lost release events left the viewer stuck rotating), and a double-click re-arms the build press state (no stacked double placement). The first atom on an empty scene seeds the trajectory WITHOUT addMolecule's camera reset, so it appears under the cursor. `X`/Del deletes the selection; hotkeys H C N O S P F L(Cl) R(Br) pick the element (ShortcutOverride-gated on viewport focus). Undo snapshots coalesce (one per 5 s of building).
- ✅ **Interaction modes** are ONE exclusive enum (`None/Edit/Measure/BondEdit/Build`) with exit/entry code in `setInteractionMode()`; `setEditMode/setMeasurementMode/setBondEditMode` are thin wrappers; `bondEditModeChanged` keeps the panel combo and the Build ▾ bond tools honest. BondEdit (add/delete bond, cycle order by clicking two atoms, which Build cannot do) is a Build sub-tool and lights the Build button. **Esc** steps back one level: drop a carried fragment → clear selection/marks → leave the tool for View (`MainWindow::handleEscape`).
- ✅ **Element picker** (`widgets/elementpicker.*`): quick strip H C N O S P F Cl Br + full periodic-table popup, visible only in Build mode; `elem::` falls back to curcuma's Z-indexed radii/colour tables for all 118 elements (`atomicNumber`/`symbolForZ`).
- ✅ **Valence consistency**: raising a bond order via `buildBond` strips one bonded H per excess valence from over-saturated endpoints (`build::excessHydrogens`, tested) — covers "build ring, add H, then aromatize".
- ✅ **Auto-hydrogens** (`buildtools.*`, `namespace build`, free functions, tested in `test_buildtools`): open valence = maxValence − Σ bond orders (S/P target H2S/PH3; metals/beads skipped); VSEPR placement via steric number = neighbours + missing + lone pairs (linear 180° / trigonal 120° / tetrahedral 109.47°). "Add H" button + open-valence label in the Build strip; per-atom via context menu.
- ✅ **Undo** (Edit ▸ Undo, Ctrl+Z): restores + consumes the newest snapshot (`MainWindow::undoLastSnapshot`, `SnapshotsWidget::removeSnapshotAt`), repeated Ctrl+Z walks back; snapshot 0 (original) is restored but never removed. Text widgets keep their own Ctrl+Z (ShortcutOverride).
- ✅ **Fragment carry** (Build dropdown): the fragment hangs on the mouse and follows it (`startFragmentCarry`/`updateFragmentCarry`); the attach atom's proximity shows the live bond preview incl. distance-implied order; click drops, **Shift+click drops a copy and keeps carrying** (serial placement), right-click/Esc cancels (carried atoms removed). Near a bonding partner the carry shows the **LIVE docked pose** (alignment + clearance-optimal roll at covalent distance, Xx hidden inside the attach atom) exactly as the drop commits it — target detection stays cursor-based (free-follow attach position), so the preview never sticks; poses are recomputed from the captured library geometry (no drift). Opt-out: Build ▾ ▸ "Live Docking Preview" (`buildDockPreview` in DisplaySettings). Saturated targets dock along the sacrificial H nearest the approach side (`dockDirection`). Context-menu "Attach Fragment" keeps the automatic docking path.
- ✅ **Container füllen** (`src/scenefiller.{h,cpp}` GUI-frei + `src/dialogs/fillcontainerdialog.*`, Build-Strip "Fill" und Structure ▸ Fill Container…): packt N zufällig orientierte Kopien von Bibliotheks-Molekülen in eine Kugel oder Box. Gleichverteilte Rotationen nach Shoemake, Rejection-Sampling für die Position, Mindestabstand zwischen Kopien (Default 2,2 Å) und zu bereits vorhandenen Atomen, Abbruch nach `maxAttemptsPerCopy` → `placed < requested` statt Endlosschleife. Seed 0 = jedes Mal neu, sonst reproduzierbar. Bindungsordnungen der Fragmente bleiben erhalten (N₂ dreifach). Alle Kopien gehen in **einen** `appendMolecule`-Aufruf → ein Undo-Schritt; auf Wunsch wird die Confinement-Wand auf den Container gesetzt. Test: `test_scenefiller`.
- ✅ **Reaktive Parameter in der GUI** — Gruppe "Reactive Topology" (nur MD + GFN-FF + react): Form-/Break-Faktor (Break-Minimum folgt dem Form-Wert, weil curcuma sonst beide still auf die Defaults zurücksetzt), Scan-Intervall, Refraktärscans, Valenzschranke, Exchange-Scans → `controller["gfnff"]["react_*"]`, nur im react-Modus geschrieben. RATTLE wird bei react gesperrt (curcuma lehnt die Kombination beim Start ab) — plus Gürtel in `buildConfig` für aus Lessons geladene Configs. Die gezeichnete Bindungsliste wird im react-Modus als Topologie an curcuma übergeben (`atomsToMolecule(atoms, &bonds)` → `setTopologyMatrix`); bewusst **nicht** in auto/constant, weil Forced-Bonds dort GFN-FFs eigene Detektion still ersetzen würden.
- ✅ **Fragment templates** (`fragmentlibrary.*`): methyl/hydroxyl/amino/carboxyl/phenyl (substituents; each carries an explicit **`Xx`/R1 attachment-point atom** bonded to `attachAtom` — curcuma polymerbuild convention, library invariants pinned in `test_buildtools`) + benzene/cyclohexane/methane/water/ammonia (standalone); ring skeletons saturated through `build::generateHydrogens`. Docking aligns the attach→Xx axis onto the target's free valence and scans the roll about the bond axis (30° steps, `dockRotation`) for the pose with maximum clearance to the scene; the Xx and a sacrificial target H are consumed. A carry-drop with a bond target re-docks through the same path (the free-floating copy is replaced); a free drop strips the Xx (open site shows via the valence indicator). Build-button dropdown + context menu "Attach Fragment".
- ✅ **New Scene** (File ▸ New Scene): `MoleculeViewer::newScene()` empties trajectory/selection/NCI but keeps the camera (first atom lands under the cursor), enters Build mode; modified structures are confirmed and stay in Snapshots.
- ✅ **Drawn bar icons**: `barIcon(kind, colour)` (anon namespace, view.cpp) paints palette-coloured glyphs (measure/edit/build/nci/photo/addh/clean/gear) at 2x DPR — replaces the desktop-dependent `QIcon::fromTheme` chains, every bar button now has a consistent icon.
- ✅ **Clean up**: bar button → `cleanupRequested` → `SimulationControlWidget::startQuickOptimization(50)` (shared `startWithConfig` lifecycle, current method, refuses while a run is active); snapshot "Before cleanup" first.
