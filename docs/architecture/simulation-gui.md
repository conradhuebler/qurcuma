# Interactive simulation (GUI side)

- ✅ **Simulation dock layout (UX-Etappe 6 S1)**: Basis = curcumas tier-"primary"-Parameter (Method-Gruppe: Method, Optimizer + Max iterations [Opt], Charge, Unpaired electrons; MD-Gruppe: Temperatur, Thermostat + passende Felder, Time step, Total steps). Jede optionale MD-Funktion (Ramp, Regions, RATTLE, RMSD-MTD, Walls) ist eine `CollapsibleSection` mit Schalter im Kopf (`addSwitch`: an = aufklappen + Inhalt aktiv, `setSwitchedOn` für `applyConfig`); Rest (GPU, Topology, H-Massenfaktor, Gradient tol, Keep params, Output) in "Advanced", zugeklappt. `hydrogen_mass` ist in curcuma ein Int → ganzzahliger Faktor.
- ✅ **Run log** (`src/runlog.h`, UX-Etappe 6 S4): Worker emittiert zu Beginn jedes MD-Laufs (`startMD`) und jeder Optimierung (`runOptimization`, nicht Clean-up, nicht Step) `runParameters(record)`: gesendete Parameter mit Wert ≠ curcuma-Default (MD gegen Registry `simplemd`, Opt gegen `GetDefaultConfiguration()` des gewählten Optimizers; charge/spin extra) mit Quelle simulation/all-parameters/qurcuma. MainWindow schreibt die Zusammenfassung ins Output-Panel und hängt den Datensatz an `run-parameters.jsonl` (AppDataLocation) an; Tools ▸ Parameter Usage zählt je Modus/Parameter/Quelle. Getestet in `test_recipes`.
- ✅ **All parameters tab** (`simulationparameterswidget.*`, UX-Etappe 6 S3, Versuch parallel zur Handoberfläche): alle nicht-deprecated `simplemd`-Parameter aus curcumas `ParameterRegistry`, nach Kategorie, Filter nach tier/Suche/„Changed only“. Was der Simulation-Tab oder qurcuma fest setzt (`SimulationWorker::handSimplemdKeys`, alle Features an), ist read-only mit dem gesendeten Wert (`handSimplemdParams`); editierbar nur der Rest, gespeichert werden nur Abweichungen vom Default (`SimulationConfig::mdExtraParams`, in Lessons/Rezepten), `applyExtraParams` überschreibt nie einen Hand-Schlüssel (auch nicht per Alias). `relevantWhen` graut aus (`simparams::conditionHolds`, getestet). Nur MD: der Optimizer-Pfad liest nicht das Registry-Modul `opt`, sondern die Defaults des gewählten Optimizers.
- ✅ **Recipes** (`src/recipe.h`, UX-Etappe 6 S2): benannte Simulationsprotokolle = `simConfigToJson` ohne `recipes::keptKeys()` (method, charge, spin, topologyMode, gpu, fpsLimit, performance*, writeTrajectory, optKeepParameters); `recipes::apply` legt das Protokoll über die aktuelle Konfiguration, ein Rezept ändert also nie das System. Eingebaut: Quick relax (curcumas loose-Preset), MD 300 K, Heat up (50→300 K), Confined (Kugelwand, auto); eigene als JSON-Array (`Settings::userRecipes`, Schlüssel `simulation/recipes`). Ein Menü (`MainWindow::populateRecipeMenu`) für Simulation ▸ Recipe und den Recipe-Knopf im Dock, während eines Laufs gesperrt. Test: `test_recipes` (auch der vollständige `SimulationConfig`-JSON-Roundtrip).
- ✅ **Charge / unpaired electrons** — curcumas primary-Parameter `charge`/`spin` (spin = ungepaarte Elektronen, 0 = Singulett) im Method-Block: MD über die `simplemd`-Parameter, Opt über `Molecule::setCharge/setSpin` vor `InitializeOptimization` (wie curcumaopt). In Lessons gespeichert.
- ✅ **RMSD-MTD bias** — `rmsd_mtd` ist kein eigener Treiber, sondern ein Bias-Modus *innerhalb* von curcuma `SimpleMD` (aktiviert via `rmsd_mtd=true` + `rmsd_mtd_*` im `simplemd`-Controller). Im Simulation-Widget Abschnitt "RMSD Metadynamics" (MD-only): k/α/atoms/ref-file/max-gaussians/max-height, **Deposit every** (`rmsd_mtd_deposit_stride`, fs) + **Hill spacing** (`rmsd_mtd_r_dep`, Å, −1 = auto FWHM(α)) für curcumas Standardschema `strided`, wtmtd+ΔT, freeze-inherited. `SimulationConfig` hält die Felder; `SimulationWorker::applyRmsdMtdParams()` (file-local) schreibt sie nur bei `rmsdMtd=true`. `rmsd_econv`/`rmsd_mtd_pace` (legacy-Schema) werden nicht gesendet (curcuma warnt sonst unter strided). Defaults aus `external/curcuma/src/capabilities/simplemd.h` "RMSD-MTD"-PARAM-Kategorie.
- ✅ **Harmonic confinement walls** — curcuma `SimpleMD` `wall_type` (none/spheric/rect) + `wall_potential` (harmonic/logfermi) + `wall_x|y|z_min/max` / `wall_radius` ("Walls"-PARAM-Kategorie, simplemd.h). Im Simulation-Widget Abschnitt "Confinement Walls" (MD-only, Schalter im Kopf): Geometry/Potential-Combo + 6 rect bounds + sphere radius, manuell einstellbar. `SimulationConfig` hält die Felder; `SimulationWorker::applyWallParams()` (file-local) schreibt sie nur bei `wallEnabled` in den Controller. Viz: `SceneController::setWallBox`/`setWallSphere` bauen 12 Kanten bzw. Lat/Long-Ringe als `BondInstancing`-Segmente (Muster wie `setMeasurement`), Model unter `moleculeRoot` (rotiert mit dem Molekül, intrinsische Koordinaten). `MainWindow::onSimulationConfigChanged` → `MoleculeViewer::setConfinementBox` zeichnet die Box live beim Tippen (auto-show when enabled); Simulation dock ▸ Show in viewer ▸ "Confinement walls" (`setWallVisibleOverride`) blendet sie unabhängig aus (`wallVisible` in `VisualizationSettings`). "Wall opacity"-Slider (`setWallOpacity` → `SceneController::wallOpacity`-Q_PROPERTY) steuert die Transparenz variabel: RGB (grau/rot) kommt pro Segment, das Alpha ist das Material-`baseColor`-Alpha (QML-Binding `Qt.rgba(1,1,1,controller.wallOpacity)`), kein Geometry-Rebuild bei Änderung. Auto-Size (Bounds/Radius = 0) wird von curcuma erst zur Laufzeit berechnet → nicht vorab zeichenbar.
- ✅ **Wand-Grenzverletzungs-Feedback** — `MoleculeViewer::computeWallViolations()` zählt pro Frame/Live-MD die Atome außerhalb der Wand (rect: Achse außerhalb [min,max]; spheric: |r|>radius), rekolloriert das Wireframe **rot** bei Verletzung (sonst grau; `SceneController::setWallColor`+`rebuildWall`), emit `wallViolationChanged(count)` → `SimulationControlWidget::setWallViolationCount` zeigt „⚠ N atoms outside / ✓ all atoms inside". Aufgerufen aus `showFrame`, `updateSimulationFrame`, `applyWallVisibility`.
- ✅ **Warum ein Lauf endet** — curcuma verbirgt jede Abbruchmeldung hinter Verbosity 1 (die GUI fährt 0), und das reguläre Zeitende meldet gar nichts; ein fertiger und ein zerfallener Lauf sahen im Dock identisch aus. `SimpleMD::stopReason()`/`stopReasonText()` liefern den Grund, `SimulationWorker::finalizeMDRun` reicht ihn über `finished(reason, aborted)` weiter. Das Dock zeigt "Finished: …" bzw. rot "Aborted: …", `runEnded` spiegelt die Zeile ins Output-Dock und in die Statusleiste.
- ✅ **Periodischer Container als dritter Wandtyp** — Confinement Walls ▸ Potential ▸ "Periodic (wrap around)" (`wallPotential` 0=harmonic, 1=logfermi, 2=pbc; der frühere Bool `wallHarmonic` wird in Lessons weiter gelesen). Übt keine Kraft aus: ein Molekül, das den Container verlässt, kommt auf der Gegenseite wieder herein — heizt also nicht, anders als die beiden Potentiale. Gemessen über 20 ps in einer 4,5-Å-Kugel (max |r| / REACT-Ereignisse): harmonic 11,00 Å / 177, logfermi 8,76 Å / 294, pbc 4,91 Å / 601. Da es kein Potential gibt, blendet der Viewer für pbc die Iso-Schalen und Kraftpfeile aus. **Bewusst unfertig**: ohne Minimum-Image im Potential werden Wechselwirkungen über die Grenze nicht fortgesetzt, und ein belegtes Ziel wird elastisch reflektiert statt umgesetzt — siehe `external/curcuma/docs/WP-PERIODIC-NONBONDED.md`.
- ✅ **Wand-Potential-Parameter + Iso-Potential-Schalen + Vektorfeld** — `wall_temp`/`wall_beta` als `TemperatureSlider` in Confinement Walls; live-anpassbar via mutex-gepufferte `SimulationWorker::setWallTemp/setWallBeta`. Display-Panel "Show potential gradient": 6 konzentrische Schalen — 3 innen (blau→grün, Annäherungszone) + 3 außen (gelb→rot, Kraftzone) — Abstände harmonic: 4/2/0.8 Å; LogFermi: 4/β, 2/β, 0.5/β; Schalen auch außerhalb der Wand (wo die Kraft tatsächlich wirkt). Display-Panel "Show force vectors" + Resolution-Spinbox (2–8): Kraft-Pfeile auf Gitternetz um die Wand (Kugel: lat/lon-Gitter; Box: res×res pro Fläche), Pfeillänge = Kraftbetrag, Farbe = Abstandsebene. Harmonic: nur außen (F=0 innen); LogFermi: auch innen (Glockenkurve). Impl: `SceneController::rebuildWallVectorField()` + `wallForceMag()` (anon-namespace); `m_wallForceShafts`/`m_wallForceTips` (`BondInstancing`); `setWallVectorField(bool, int)` durch alle Layer bis `MainWindow`.
- ✅ **Stale-`stop`-File-Guard** — curcuma `CurcumaMethod::CheckStop()` (curcumamethod.cpp) bricht `SimpleMD::step()` sofort ab, wenn eine Datei `stop` im CWD liegt (CLI-Interrupt-Mechanismus). qurcuma steuert den Abbruch interaktiv über `requestStop()`, nicht über die Datei. Eine leftover `stop`-Datei aus einem früheren curcuma-CLI-Lauf im selben Verzeichnis hat daher jeden interaktiven MD/Opt-Lauf bei Step 0 abgebrochen (`step()` false beim ersten Aufruf, `m_run_prepared` true → finalize druckt Initialframe + „Exchange with heat bath", null Integrationsschritte = „MD startet nicht"-Symptom). `SimulationWorker::run()` entfernt `CWD/stop` vor jedem Run.
- ✅ **Thermostat-Auswahl** — Combo im Simulation-Widget (MD Parameters): CSVR/Berendsen/**Andersen**/Nosé-Hoover/None → `SimulationConfig::thermostat` + `coupling`/`andersen_probability`/`chain_length` (alle in `startMD` in den `simplemd`-Controller geschrieben; curcuma liest nur die zum Typ passenden). Coupling/Andersen-p/NH-chain werden je nach Auswahl aktiviert. Andersen (stochastische Geschwindigkeits-Neuzuweisung) thermalisiert Einzelatome/Gasphase besser als CSVR. Engine: `external/curcuma/src/capabilities/simplemd.h` "Thermostat"-PARAM-Kategorie (Typo `anderson`→`andersen` in curcuma bereinigt, ohne Alias).
- ✅ **Laufzeit-Temperatur: Slider + Rampen + Regionen** — vertikaler temperatur-farbiger Slider (`src/widgets/temperatureslider.*`, blau→rot, editierbares Min/Max) ersetzt die Temperatur-Spinbox und bleibt **während des Laufs aktiv**. Drag → `SimulationControlWidget::temperatureChanged` → `MainWindow::wireSimulationWorker` (QueuedConnection) → `SimulationWorker::setTargetTemperature` → setzt `SimpleMD::setTargetTemperature` vor dem nächsten Step (Muster wie Grab-Force, mutex-gepuffert in `performMDStep`); überschreibt eine laufende globale Rampe. QGroupBox "Temperature Ramp" (Enable→Tabelle Target/Mode/Value → `temp_schedule`-String) + "Temperature Regions" (Tabelle Atoms/Start T/Schedule → `temp_regions`-JSON-Array), MD-only, im Lauf gesperrt. `SimulationConfig`: `tempRamp`/`tempSchedule`/`tempRegions`; `SimulationWorker::applyTempRampParams()` (file-local) schreibt sie in den `simplemd`-Controller. Engine: `external/curcuma/docs/TEMPERATURE_RAMP.md`.
- ✅ **Verfolgte Größen im Chart** (`src/measurements.{h,cpp}` als **Qt-Adapter über curcuma** + `simulationchart.*`) — beliebig viele Abstände (2 Atome), Winkel (3), Diederwinkel (4) sowie **RMSD zum ersten Frame** und **Gyrationsradius** werden pro Frame aus `SimulationFrame::positions` berechnet und geplottet. Die Geometrie selbst liegt in curcuma (`GeometryTools::Distance/Angle/Dihedral/GyrationRadius`, `RMSDFunctions` für den Kabsch-Fit), nicht hier: curcuma braucht dieselben Größen in eigenen Capabilities, und eine zweite Implementierung in der GUI würde davon abdriften. Das Histogramm bindet **jede** aufgezeichnete Größe, mehrere gleichzeitig, über eine Auswahlliste im Histogramm-Reiter — Energien und Temperatur eingeschlossen, nicht nur die Messgrößen. Anlegen im Chart-Dialog über "Add from selection": die im Viewer markierten Atome bestimmen die Art. Zwei Ansichtsmodi: **gleitendes Fenster** über die letzten N ps und **akkumuliert**; der Modus bestimmt sowohl den sichtbaren Zeitbereich als auch, welche Werte ins **Histogramm** (eigener Reiter) einsortiert werden. **Normierungs-Umschalter** skaliert jede Größe auf 0…1 über den gezeigten Bereich, damit Å und Grad in einem Plot vergleichbar sind; ohne ihn weist ein Hinweis auf gemischte Einheiten hin. Jedes Diagramm liegt in einem eigenen Reiter (Temperature / Energy / Measurements / Histogram), Steuerleiste und Messtabelle sind geteilt. Rohwerte gehen per **CSV-Export** raus (Zeit, Energien, Temperatur, alle Messgrößen), unabhängig von Modus und Normierung. Messwerte werden als Vektoren gehalten und die Serien daraus neu aufgebaut, sodass Fenster, Normierung und Binzahl rückwirkend wirken. Das Histogramm ist eine Stufenlinie, keine Balkenserie: CuteCharts `ChartView` setzt bei jeder Serie eine `QValueAxis` voraus und würde an der `QBarCategoryAxis` einer Balkenserie in einen Null-Zeiger laufen. Der Viewer-HUD nutzt dieselben Funktionen wie die Plots, damit abgelesene und geplottete Zahlen nicht auseinanderlaufen. Test: `test_measurements`.
- ✅ **Charts als Dock** (`src/docks/chartdock.*`) — die Diagramme sind kein Dialog mehr, sondern ein reguläres Dock unten neben dem Output-Log (auch rechts andockbar), anfangs ausgeblendet. Damit nehmen die Charts an den Panels der Modi und am gespeicherten Dock-Zustand teil.
- ✅ **Live-Charts** (`src/widgets/simulationchart.*`, CuteChart `ListChart` + QtCharts): im Charts-Dock (siehe oben) mit Zeitreihen-Charts — Temperatur (instantan + Sollwert/Rampe) und Energie (E_pot/E_kin/E_tot). `SimulationFrame` trägt `temperature`/`targetTemperature` (aus `SimpleMD::currentTemperature()`/`targetTemperature()`); `MainWindow::wireSimulationWorker` verbindet `frameReady` → `ChartDock::appendFrame` (QueuedConnection) + `reset()` pro Run. - ✅ **Kraftfeld-Topologie im Viewer (reaktives GFN-FF)** — bei `topology_mode=react` trägt jedes `SimulationFrame` die Bindungsliste des Kraftfelds (`bonds`, mit Bindungsordnungen 1/2/3), einen `topologyVersion`-Zähler und die Ereignisse dieses Schritts (`events`). `SimulationWorker::collectReactiveTopology` liest sie im Worker-Thread direkt nach `step()` über `liveGfnff()` (CPU-, CUDA- und ROCm-Wrapper) aus `reactiveBonds()`/`reactiveBondOrders()`/`consumeReactEvents()`; kopiert wird nur, wenn der Rebuild-Zähler sich bewegt hat. `updateSimulationFrame` zeichnet diese Liste **statt** der eigenen Hysterese (siehe nächster Punkt) — gezeichnete und gerechnete Topologie sind damit identisch, N≡N erscheint als Dreifachbindung. Außerhalb von react bleibt `frame->bonds` leer und alles läuft wie bisher.
- ✅ **Reaktionsereignisse** — Gruppe "Reaction Events" im Simulation-Dock (nur bei MD + GFN-FF + react sichtbar): Tabelle Step/t/Ereignis/ΔE, `reactionEvent`-Signal spiegelt jede Zeile ins Output-Dock und löst bei angehakter Box einen Snapshot aus. Im Viewer blitzen die beteiligten Atome 500 ms bernsteinfarben (`SceneController::setFlashAtoms`, eigene Liste neben Kollision/Selektion); im Energie-Chart markiert eine Scatter-Serie die Ereignisse auf E_pot.
- ✅ **Dynamische Bindungen** (`MoleculeViewer::updateSimulationFrame`, `m_dynamicBonds` default an, **geometrischer Rückfall**: greift nur, wenn das Frame keine Kraftfeld-Bindungen trägt): pro Live-Frame (MD **und** Opt) wird der Bindungsgraph aus der neuen Geometrie neu erkannt (`detectBondsHysteresis` — Kovalenzradien × Toleranz mit Hysterese form 1.25 / break 1.45 gegen Flackern), sodass Bindungsbruch/-bildung in Reaktionen gezeichnet werden. Nur bei echter Topologieänderung (`bondSetEqual`, mengen-basiert) ruft es `SceneController::updateBonds()` (rebuild der Bond-Instancing-Geometrie ohne `recomputeBounds`/`resetView` → keine Kamerasprünge); stabile Frames bleiben auf `updatePositions`. Toggle: Simulation dock ▸ Show in viewer ▸ "Dynamic bonds (reactions)". Kosten O(N²)/Frame.
- Mouse grab distributes a screen-space drag as Eh/Bohr force across bonded shells (Angstrom-to-Bohr corrected in `computeGrabForce`)
- Grab force is **sticky**: `injectForce` holds it until `clearInjectedForce` (mouse release), and the worker *re-reads* (`currentInjectedForces`, peek not drain) it every MD step / Opt iteration. The viewer only emits `atomForceRequested` on mouse-*move* + once per frame, so the old one-shot drain dropped the bias whenever the cursor held still — fatal for Opt (no momentum: it relaxes straight back). Sticky = "force acts as long as the button is held"
- Opt grab needs all three: (1) sticky force (above); (2) `runOptimization` pumps `QCoreApplication::processEvents()` in the step callback so queued `injectForce`/`clearInjectedForce` reach the worker (its event loop is blocked in synchronous `Optimize()`; the dispatcher exists — MD's `QTimer` fires — so the pump delivers; MD never blocks so it needs no pump); (3) curcuma applies the bias at each optimizer's own gradient eval (LBFGSpp objective, native `LBFGS::getEnergyGradient`, ANCOpt) — the old base-loop bias was inert
- Reset restores snapshot index 0, which is captured automatically when a molecule is loaded
- Snapshots tab provides manual take/restore/delete history plus an auto-snapshot stride in Simulation tab (every N steps/iterations, 0 = off)
- GPU dropdown shows only compiled backends (CUDA/ROCm/Vulkan via `USE_*` CMake options); curcuma `feature/vulkan_rocm` branch
- CLI `qurcuma <file> -md|-opt` loads the file and auto-starts the interactive simulation from bash
- Release/AVX-512 start crash fixed: `CMakeLists.txt` matches curcuma's `-march=native` on the qurcuma target so both share Eigen's `EIGEN_MAX_ALIGN_BYTES` (mismatch caused `double free` in `moleculeToFrame`)
