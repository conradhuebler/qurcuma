# VTF/XYZ Parsers, 3D Viewer, Mouse Interactions

## Parsing
- VTF format supports periodic boundary conditions
- XYZ format reads atomic coordinates and optional velocities
- Both formats handle large files efficiently
- ✅ **VTF coarse-grained beads** — the `atom` record is parsed **keyword-based** (radius/name/type/element in any order), not by fixed columns. Element = explicit `element`, else `name` if it's a real symbol (`elem::isElementSymbol`), else empty. Beads keep their own `radius` + `type` on `Atom` (both threaded into `AtomDatum`); the renderer sizes by `radius` (fallback element vdW) and colours "By Type". Replaced the old hard-coded `ppo1→C`/`dmaema→N`/else→C fake-element table that rendered every non-polymer VTF as carbon.

## 3D Viewer (Qt Quick 3D / Vulkan)
- ✅ **Renderer = Qt Quick 3D on the Vulkan RHI** (migrated off Qt3D, which is fully removed). `MoleculeViewer` (`view.*`) stays a `QWidget` with its public API unchanged, but internally wraps a `QQuickWidget` (composited like a normal widget, so docks/menus can overlap it; `QURCUMA_NATIVE_VIEWPORT=1` = old `QQuickView`/`createWindowContainer` route) + `SceneController` view-model (`scenecontroller.*`) + `src/qml/viewer3d.qml`. Atoms/bonds = `QQuick3DInstancing` (`atominstancing.*`/`bondinstancing.*`); effects via `ExtendedSceneEnvironment` (SSAO/Bloom/HDR/Tonemap/Fog) + world-fixed cast shadows.
- **Performance roadmap** — `docs/WP-performance.md` (P0 measure → P3 latest-wins frames → P1 bonds in worker + cell list → P2 position-only instancing → P5 adaptive GPU quality → P4 NCI/collisions off-thread; render thread parked). P0 (coarse GUI-side bond/rebuild timing, `MoleculeViewer::setPerformanceAnalysis`) and P3 (frame coalescing, `MoleculeViewer::onWorkerFrameReady`) are ADDED. **ADD** remaining: P1 bonds in worker + cell list still O(N²) `detectBondsHysteresis` on the GUI thread every MD step, then P2/P5/P4.
- Vulkan chosen in `main.cpp` via a probe (`QVulkanInstance::create()`) with OpenGL fallback; override `QSG_RHI_BACKEND`. In this Qt build `QQuick3DViewport`/`Camera` are PRIVATE headers → the camera is axis-aligned and C++ replicates its projection for picking/grab (no private headers). The molecule rotates under `moleculeRoot`; the camera stays fixed. [[quick3d-private-headers]]
- Rendering modes (ball-stick/space-filling/wireframe/sticks), color schemes (CPK/mono/by-charge/**by-type** for CG beads → `SceneController::typeColor`, deterministic hue per type label), per-atom draw radius (`atomDrawRadius`: bead radius override or element vdW), transparency, atom/bond size — all in `SceneController`. `schemeColor(AtomDatum)` is the single colour source for atoms **and** bonds **and** overlays. RMSD overlays = a **list** of aligned structures (`m_overlays`) packed into the two overlay instancing buffers by `rebuildOverlays()`; each **inherits the global display styles** (mode/scale/bond/transparency/base scheme) and adds a per-structure colour **tint** (`shiftOverlayColor(base,tint)`, hue/sat shift over `schemeColor`, element identity kept) + **size**. `rebuildGeometry()` calls `rebuildOverlays()` so style changes propagate; API = `addOverlayStructure`/`setOverlayTint`/`setOverlaySize`/`setOverlayVisible`/`removeOverlayStructure`/`clearOverlay`. `setPrimaryVisible(bool)` hides/shows the primary (reference) structure (RMSD workspace).
- ✅ **Per-atom overlay labels** (Appearance ▸ Style ▸ "Labels": Element/Type/Index + "selected only"; also View ▸ Atom Labels): `SceneController::rebuildLabels()` builds a `QVariantList` of `{px,py,pz (local), text}` (rebuilt on structure/selection/live-frame/mode change only); `viewer3d.qml` `Repeater` **projects each to screen reactively** (mirrors the C++ axis-aligned camera: quaternion-rotate local−center by `rootRotation`, camera at `pivotPosition+(0,0,cameraDistance)`), so rotation/zoom/pan need no C++ recompute. Element mode falls back to bead `type` when there is no element.
- ✅ **Hydrogen display** (View ▸ Hydrogens, key `H` cycles; visual only): All / Polar (skeletal-formula convention: an H bonded only to C is hidden) / None. Rule = `SceneController::computeHydrogenMask` (tested in `test_fragments`); hidden atoms are not drawn, labelled or pickable, their bonds are skipped, an NCI line starts at the H's bonded atom; overlays follow. Build mode always shows all H (`MoleculeViewer::pushHydrogenDisplayToScene`). Persisted as `hydrogenDisplay` in `DisplaySettings`.
- **ADD (zu klären): Charge source for "By Charge"** — today charges only arrive as a side product of the GFN-FF/GFN2 NCI analysis (`NciAnalysisWorker` → `chargesReady` → `setAtomCharges`, current frame only). Options: request GFN-FF EEQ charges directly, or take partial charges from calculations/files; live MD open.
- ✅ **Hide molecules by kind** (View ▸ Hide Molecules, bar button next to H; display only): fragments grouped by formula (`SceneController::moleculeKinds`, most numerous first), hidden through the same mask as the H display (`isAtomHidden`); NCI contacts to a hidden molecule are dropped (pi-stacking centroids and RMSD overlays not covered). The viewer owns the choice (`MoleculeViewer::setHiddenMoleculeKinds`), resets it in `setTrajectoryData` and ignores it in Build mode; not persisted. Tested in `test_fragments`.
- ✅ **Looks** (`src/look.h`, UX stage 3): a look = colour scheme, material, fog, SSAO, bloom, HDR/exposure, corner lights, background, and nothing else. `MoleculeViewer::applyLook` calls only those setters, so a look can never switch a quick toggle (NCI, H display, hidden molecules, labels, render style). Built-ins in code (`looks::builtIn`: Default, Publication, Presentation, Flat (Teaching)); user looks as one JSON array (`Settings::userLooks/saveUserLook/deleteUserLook`). One menu (`MainWindow::populateLookMenu`, rebuilt on open) serves the bar's Look ▾, View ▸ Look, the context menu and the palette; the export dialog picks View (camera) and Look separately and stores both names in the PNG. The pre-2026-09 display presets were dropped once (`dropLegacyDisplayPresetsOnce`, operator decision).
- ✅ **Last session is restored**: `MainWindow::closeEvent` saves `currentDisplaySettings()` (incl. background, corner lights, fog distance), `setupUI` applies it at startup; Save/Load Defaults are gone, the panel keeps only "Reset to Factory Settings". NCI option changes emit `nciOptionsChanged` (Hydrogen Bonds quick toggle `Shift+N` ↔ panel checkbox).
- ✅ **Screen-fixed corner lights** (◤◥◣◢): `DirectionalLight`s parented to the QML camera (lit zone stays view-fixed); a separate world-fixed key light casts shadows. Toggled via `SceneController` cornerLight properties.
- ✅ **Image export** (File ▸ Export Image…, Ctrl+Shift+E → `MoleculeViewer::exportImageDialog`/`exportImage`): true high-res **offscreen render via `QQuickRenderControl` + `QRhi`** (needs `Qt6::GuiPrivate`, `#include <rhi/qrhi.h>`) — render the QML scene to a `QRhiTexture` at the chosen resolution and read it back. `grabWindow()` on a hidden window returns blank (threaded render loop), so the render control drives rendering synchronously. Uses a **separate** `SceneController` (`cloneStateFrom`, no scene-graph node sharing) and reuses the live view's `QVulkanInstance` for the Vulkan backend; OpenGL needs `result.mirrored()` (`rhi->isYUpInFramebuffer()`). Dialog: width/height (default 2× viewport), background (transparent default/white/scene), SSAA toggle; default folder = current workspace. Export-only `SceneController` props `highQualityAA` (SSAA VeryHigh) + `transparentBackground` bound in `viewer3d.qml`; transient overlays (selection/measurement/force vectors) are not cloned → clean image.

## Non-Covalent Interactions (NCI Overlay)
- ✅ **Geometrische Erkennung** (`ncianalysis.{h,cpp}`, `namespace nci`, freie Funktionen, keine Klasse): H-Brücken (2.50 Å H···A / 130° D-H···A), Halogenbrücken (0.95·Σr_vdW / 150°, F ausgeschlossen), π-Stacking (planare 5-/6-Ringe, Zentroid ≤ 5.5 Å, parallel ≤ 30° + Versatz ≤ 2.0 Å oder T-förmig ≥ 60°), vdW-Nahkontakte (0.90·Σr_vdW, default aus). Literaturstellen stehen als Doxygen-Kommentar an `detectGeometric()`.
- **Radien**: `nci::vdwRadius()` nutzt curcumas `Elements::VanDerWaalsRadius` — **nicht** `elem::vdwRadius()`, das ist ein Zeichenradius (H = 0.5 Å, 16 Elemente).
- **Ringe**: curcumas header-only `Topology::FindRings` (maxsize 8), nur bei Topologieänderung; Cache `m_nciRings` im Viewer, invalidiert bei jedem `fullRebuild` und bei dynamischer Bindungsänderung.
- **Datentypen** in `ncitypes.h` (ohne `view.h`), damit `view.h` `nci::Options`/`nci::Result` als Member halten kann; `ncianalysis.h` zieht beide zusammen.
- **Overlay**: `SceneController::setNciContacts` → `rebuildNci()` baut gestrichelte Linien aus kurzen `#Cylinder`-Segmenten (kein Dash-Primitive in Quick3D), Alpha in die Instanzfarbe eingebacken + `alphaMode: Blend` im QML (dieselbe Falle wie beim Wall). Model unter `moleculeRoot`; Beschriftung über eine zweite `QVariantList nciLabels` mit dem kopierten `Text`-Delegate.
- **Einstieg pro Frame**: `MoleculeViewer::refreshNciOverlay()` hängt am Ende von `syncSceneToController()` (deckt Frame-Wechsel, Live-MD, Edit, Refresh ab) plus `finalizeEdit()`.
- **Berechnete Quellen**: `ncianalysisworker.{h,cpp}` auf eigenem Thread (der Sim-Thread ist vom MD-Timer belegt). GFN-FF liefert eine **Kandidaten**-Enumeration (>5000 Tripel bei 114 Atomen) — `applyGeometricGate()` reduziert sie auf die im Frame eingegangenen Terme. Pro-Kontakt-Energien für HB/XB existieren in GFN-FF nicht; Coulomb und D4-Dispersion dagegen sind aus den Parametern geschlossen berechenbar.
- **Live-MD** (Opt-in): `SimulationWorker::setLiveNci` setzt `hb_update_force_every=1` und legt die HB/XB-Listen in `SimulationFrame::nciContacts`.
- **Farben frei wählbar**: `nci::Palette` (`QHash<int,QColor>`, Schlüssel = `nci::paletteKey()`; Elektrostatik ist nach Vorzeichen in zwei Schlüssel getrennt) liegt im Viewer, wird von `pushNciToScene()` und der Kontakttabelle gelesen. Bead-Typ-Farben als `QHash<QString,QColor>` in `SceneController` (`typeColor()` prüft erst den Override). Beide persistiert in eigenen QSettings-Gruppen (`visualization/beadColors`, `visualization/nciColors`), beide in `cloneStateFrom` mitkopiert.
- **Fragment-Einfärbung (Wirt-Gast)**: `SceneController::ensureFragments()` bildet die Zusammenhangskomponenten des Bindungsgraphen, sortiert **nach Atomzahl absteigend** (Fragment 0 = größtes = Wirt, bleibt ungetönt) und baut je Fragment die Hill-Summenformel. `applyFragmentTint()` verschiebt über `tintFragmentColor()` nur den Farbton (Sättigungsboden für Grautöne, kein Abdunkeln) mit einstellbarer Stärke; `schemeColorFor(index)` ist der indexbasierte Einstieg, den Atome und Bindungshälften nutzen. Faul berechnet, `m_fragmentsDirty` bei `setStructure`/`updateBonds`/`clear`. `atomDrawRadiusFor(index)` multipliziert zusätzlich `fragmentScaleFor()` auf den Zeichenradius; wirkt auf Atome, Bindungsdicke und die Endpunktkürzung der NCI-Striche. Farbe, Tönungsstärke und Größe sind je Fragment überschreibbar (`m_fragmentColors`/`m_fragmentStrengths`/`m_fragmentScales`) über einem gemeinsamen Vorgabewert; `clearFragmentOverrides()` setzt alle drei zusammen zurück. **Bedienmodell**: die Combobox im Display-Panel wählt das Fragment, der Kasten darunter trägt dessen Namen im Titel und wirkt ausschließlich darauf - kein global wirkender Regler daneben. Persistiert als `fragmentTint`/`fragmentTintStrength`/`fragmentScale` in `DisplaySettings`; die Farbüberschreibungen pro Fragment sind strukturspezifisch und werden bewusst **nicht** gespeichert. Test: `test_fragments`.
- **Bead-Typ-Liste**: `SceneController::beadTypes()` zählt die `type`-Labels der aktuellen Struktur (alphabetisch, mit Anzahl) — das Display-Panel baut sein Auswahlfeld daraus, statt aus einer festen Tabelle. `MoleculeViewer::beadTypesChanged()` feuert bei jedem `fullRebuild`.
- Tests: `test_nci` (Kriterien), `test_nci_gfnff` (curcuma-Pfad, braucht `release/conf_28.xyz`).

Toggle: Simulation dock ▸ Show in viewer ▸ "Dynamic bonds (reactions)". Kosten O(N²)/Frame.
- Mouse grab distributes a screen-space drag as Eh/Bohr force across bonded shells (Angstrom-to-Bohr corrected in `computeGrabForce`)
- Grab force is **sticky**: `injectForce` holds it until `clearInjectedForce` (mouse release), and the worker *re-reads* (`currentInjectedForces`, peek not drain) it every MD step / Opt iteration. The viewer only emits `atomForceRequested` on mouse-*move* + once per frame, so the old one-shot drain dropped the bias whenever the cursor held still — fatal for Opt (no momentum: it relaxes straight back). Sticky = "force acts as long as the button is held"
- Opt grab needs all three: (1) sticky force (above); (2) `runOptimization` pumps `QCoreApplication::processEvents()` in the step callback so queued `injectForce`/`clearInjectedForce` reach the worker (its event loop is blocked in synchronous `Optimize()`; the dispatcher exists — MD's `QTimer` fires — so the pump delivers; MD never blocks so it needs no pump); (3) curcuma applies the bias at each optimizer's own gradient eval (LBFGSpp objective, native `LBFGS::getEnergyGradient`, ANCOpt) — the old base-loop bias was inert
- Reset restores snapshot index 0, which is captured automatically when a molecule is loaded
- Snapshots tab provides manual take/restore/delete history plus an auto-snapshot stride in Simulation tab (every N steps/iterations, 0 = off)
- GPU dropdown shows only compiled backends (CUDA/ROCm/Vulkan via `USE_*` CMake options); curcuma `feature/vulkan_rocm` branch
- CLI `qurcuma <file> -md|-opt` loads the file and auto-starts the interactive simulation from bash
- Release/AVX-512 start crash fixed: `CMakeLists.txt` matches curcuma's `-march=native` on the qurcuma target so both share Eigen's `EIGEN_MAX_ALIGN_BYTES` (mismatch caused `double free` in `moleculeToFrame`)

## Mouse Interactions (C++ `eventFilter` on the viewer's `QQuickWindow`)
- Left-drag = rotate (model rotation); right-drag = pan; wheel = zoom; middle-click = reset view.
- Left-**click** (no drag) = ray-pick an atom → select (Ctrl/Shift = add to selection).
- ✅ **Hover feedback**: moving over an atom brightens it (`SceneController::setHoverAtom`, cheap atoms-only `rebuildAtoms`, only on change) + pointing-hand cursor; cleared on leave.
- In sim mode, left-press on an atom + drag = grab → `atomForceRequested` (see Interactive Simulation).
- ✅ **Measurement**: a single "Measure" tool (viewer bar); the type is auto-detected from the number of picked atoms (2 = distance, 3 = angle, 4 = dihedral). Click marks an atom, click it again to de-mark, Esc clears. The HUD shows ALL pairwise distances + chain angles + dihedral (`MoleculeViewer::updateMeasurement` → `SceneController::setMeasurement`). Lines and values follow frame jumps (`showFrame`), playback (`updateFramePositions`) and live MD/Opt (`updateSimulationFrame` → `updateMeasurement(0)`, the frame the live path writes).

## Structure Editing (Explore-mode "Edit" toggle)
- ✅ **Edit mode** (`MoleculeViewer::setEditMode`, viewer-bar "Edit" toggle; sibling of Measure, exclusive with measure/bond-edit) — direct coordinate editing, **distinct from the sim grab-force** (which injects forces into running MD/Opt). `eventFilter` Edit branch: click = select atom, **double-click = whole molecule** (`selectFragment`, BFS over the current bond graph via `forceinjector::buildAdjacency`), drag on atom = move (Shift = depth), drag empty = rotate, **Ctrl/Shift+drag empty = rubber-band box-select** (`SceneController::atomsInScreenRect` + a 2D QML overlay rect via `setRubberBand`), click empty = clear.
- ✅ **WASD/QE scene rotation** (W/S pitch, A/D yaw, **Q/E roll** → full 3-axis) — application-level key filter `MainWindow::eventFilter` (installed on `qApp`), **active in Edit mode and the interactive MD/Opt grab mode** (`simulationActive()`; rotation is purely visual there) so the keys stay free everywhere else; also skipped while a text widget has focus or Ctrl/Alt/Meta is held. Calls `MoleculeViewer::rotateSceneByKey` → `applyModelRotation` (shared with mouse rotate). **Shift+WASDQE** nudges the selection (Q/E = depth). Gives the depth DOF a 2D in-plane move can't reach.
- ✅ **Deselect** — **right-click (no pan-drag)** clears the selection (and measurement marks); right-drag still pans. Plain left-click on empty space in Edit mode also clears.
- ✅ **Edit hint HUD** — bottom-centre 2D overlay (`SceneController::editHint` Q_PROPERTY → `viewer3d.qml`) listing the key/mouse bindings; shown while Edit mode is on (set in `setEditMode`), empty string = hidden.
- ✅ **Move** — `SceneController::screenDragToModelDelta` (translation twin of `computeGrabForce`: same pixel→world-at-depth scale, Ångström not Bohr, no force factor) → `moveSelection` adds the delta to atom positions via the cheap `updatePositions` path (no camera jump).
- ✅ **Cursor lock while dragging** (`m_dragCursorLock`, default on; Edit ▸ Preferences ▸ "Lock Cursor While Dragging") — warps the cursor back to the press point each move so the drag is relative/infinite and never runs off-screen (a zero-delta guard absorbs the synthetic warp move). Needs X11 cursor warping; on Wayland `QCursor::setPos` may be a no-op (drag still works, cursor just isn't pinned).
- ✅ **Collisions** — `computeCollisions` (O(N²): clash if dist < `kClashFactor`=0.6 × (vdW_i+vdw_j); skips bonded pairs + pairs both inside the selection) → `SceneController::setCollisionAtoms` recolours them **red** (priority above the magenta selection in `atomColor`); `collisionCountChanged` → viewer-bar "⚠ N clashes / ✓ no clashes". **Resolve clashes** button = `resolveClashes` (rigid translation of the selection along the overlap-weighted net push until clear).
- ✅ **Copy/Paste/Delete** (Edit menu; Ctrl+C/Ctrl+V context-aware: selection in Edit mode, structure text otherwise) — `copySelection`/`pasteClipboard` (re-indexed internal bonds, paste offset) and `deleteSelection` (reindexes bonds). Count-changing ops are single-frame only (`canEditStructure`, `frameCount<=1`).
- ✅ **Merge from file** (`Structure ▸ Add Molecule to Scene…` + `MainWindow::parseFirstFrame`) — `MoleculeViewer::appendMolecule` appends + selects + starts placement via a **bounds-preserving** rebuild `SceneController::setStructure(..., keepView=true)` (no `recomputeBounds`/`resetView`, else a rotated molecule jumps by (I−R)·Δcenter).
- ✅ **Undo** — viewer emits `editSnapshotRequested(label)` before each mutating op → `MainWindow::takeSnapshot`; restore via the Snapshots tab.

## Molecule Builder (Build mode)
- ✅ **Build mode** (`InteractionMode::Build`, viewer-bar "Build" split-button, Structure ▸ Build (key B), Esc steps back to View): click empty space = place atom of the current element at the selection's depth (`SceneController::screenToModelPoint`, inverse of the pick ray); click an atom = change it to the current element; **middle-click** an atom = attach a bonded atom along `freeValenceDirection` (−Σ unit bond vectors) at covalent distance; **right-click** an atom = delete it (elsewhere right-click keeps the context menu); drag = the atom follows the cursor LIVE (move intent); the atom always follows the cursor; bond intent is PROXIMITY-based (within 1.35 × Σrcov of an unbonded atom: highlight + REAL preview bond whose ORDER follows the current distance live — `build::bondOrderFromDistance`, C-C series ratios; release commits atom position and that order). Cursor directly on a bonded neighbour on release = cycle order (atom returns to start, it was a gesture) (removed on leave, committed via `buildBond` on release; `pickAtom` excludes the dragged atom so it cannot occlude the target); release on empty keeps the move (no bond re-detection — the builder keeps the drawn topology). **Ctrl+drag or held Space = pure navigation** (rotate) even from an atom; **Shift+drag on an atom = depth move** (Edit-mode convention; plane drags keep the atom's current depth); **keys 1/2/3 while a bond preview is on screen force the order** (`setForcedBondOrder`, ShortcutOverride-gated — without a preview they keep the render styles; the forced order dies with its preview). Carry previews always show order 1 (docking commits a single bond). Robustness: MouseMove re-syncs `m_leftMousePressed` from `me->buttons()` (lost release events left the viewer stuck rotating), and a double-click re-arms the build press state (no stacked double placement). The first atom on an empty scene seeds the trajectory WITHOUT addMolecule's camera reset, so it appears under the cursor. `X`/Del deletes the selection; hotkeys H C N O S P F L(Cl) R(Br) pick the element (ShortcutOverride-gated on viewport focus). Undo snapshots coalesce (one per 5 s of building).
- ✅ **Interaction modes** are ONE exclusive enum (`None/Edit/Measure/BondEdit/Build`) with exit/entry code in `setInteractionMode()`; `setEditMode/setMeasurementMode/setBondEditMode` are thin wrappers; `bondEditModeChanged` keeps the panel combo and the Build ▾ bond tools honest. BondEdit (add/delete bond, cycle order by clicking two atoms, which Build cannot do) is a Build sub-tool and lights the Build button. **Esc** steps back one level: drop a carried fragment → clear selection/marks → leave the tool for View (`MainWindow::handleEscape`).
- ✅ **Element picker** (`widgets/elementpicker.*`): quick strip H C N O S P F Cl Br + full periodic-table popup, visible only in Build mode; `elem::` falls back to curcuma's Z-indexed radii/colour tables for all 118 elements (`atomicNumber`/`symbolForZ`).
- ✅ **Valence consistency**: raising a bond order via `buildBond` strips one bonded H per excess valence from over-saturated endpoints (`build::excessHydrogens`, tested) — covers "build ring, add H, then aromatize".
- ✅ **Auto-hydrogens** (`buildtools.*`, `namespace build`, free functions, tested in `test_buildtools`): open valence = maxValence − Σ bond orders (S/P target H2S/PH3; metals/beads skipped); VSEPR placement via steric number = neighbours + missing + lone pairs (linear 180° / trigonal 120° / tetrahedral 109.47°). "Add H" button + open-valence label in the Build strip; per-atom via context menu.
- ✅ **Undo** (Edit ▸ Undo, Ctrl+Z): restores + consumes the newest snapshot (`MainWindow::undoLastSnapshot`, `SnapshotsWidget::removeSnapshotAt`), repeated Ctrl+Z walks back; snapshot 0 (original) is restored but never removed. Text widgets keep their own Ctrl+Z (ShortcutOverride).
- ✅ **Fragment carry** (Build dropdown): the fragment hangs on the mouse and follows it (`startFragmentCarry`/`updateFragmentCarry`); the attach atom's proximity shows the live bond preview incl. distance-implied order; click drops, **Shift+click drops a copy and keeps carrying** (serial placement), right-click/Esc cancels (carried atoms removed). Near a bonding partner the carry shows the **LIVE docked pose** (alignment + clearance-optimal roll at covalent distance, Xx hidden inside the attach atom) exactly as the drop commits it — target detection stays cursor-based (free-follow attach position), so the preview never sticks; poses are recomputed from the captured library geometry (no drift). Opt-out: Build ▾ ▸ "Live Docking Preview" (`buildDockPreview` in DisplaySettings). Saturated targets dock along the sacrificial H nearest the approach side (`dockDirection`). Context-menu "Attach Fragment" keeps the automatic docking path.
- ✅ **Fragment templates** (`fragmentlibrary.*`): methyl/hydroxyl/amino/carboxyl/phenyl (substituents; each carries an explicit **`Xx`/R1 attachment-point atom** bonded to `attachAtom` — curcuma polymerbuild convention, library invariants pinned in `test_buildtools`) + benzene/cyclohexane/methane/water/ammonia (standalone); ring skeletons saturated through `build::generateHydrogens`. Docking aligns the attach→Xx axis onto the target's free valence and scans the roll about the bond axis (30° steps, `dockRotation`) for the pose with maximum clearance to the scene; the Xx and a sacrificial target H are consumed. A carry-drop with a bond target re-docks through the same path (the free-floating copy is replaced); a free drop strips the Xx (open site shows via the valence indicator). Build-button dropdown + context menu "Attach Fragment".
- ✅ **New Scene** (File ▸ New Scene): `MoleculeViewer::newScene()` empties trajectory/selection/NCI but keeps the camera (first atom lands under the cursor), enters Build mode; modified structures are confirmed and stay in Snapshots.
- ✅ **Drawn bar icons**: `barIcon(kind, colour)` (anon namespace, view.cpp) paints palette-coloured glyphs (measure/edit/build/nci/photo/addh/clean/gear) at 2x DPR — replaces the desktop-dependent `QIcon::fromTheme` chains, every bar button now has a consistent icon.
- ✅ **Clean up**: bar button → `cleanupRequested` → `SimulationControlWidget::startQuickOptimization(50)` (shared `startWithConfig` lifecycle, current method, refuses while a run is active); snapshot "Before cleanup" first.
